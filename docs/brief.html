The user

A ZainCash support agent. One queue, three ways of writing: Iraqi dialect, English and Arabic in Latin letters.

The problem

Every ticket is read by hand just to learn what it is and who owns it. Money problems wait in the same line as questions about fees.

What changes

Farz does the reading and sorting. The agent only approves, edits or takes over. No reply leaves without a person.

How it works

Every ticket takes the same five steps.

1
Batch in
Tickets from the app and support channels, grouped every few minutes.
2
Jev decides
Category, priority and team, each with a confidence.
3
Rules extract
Amount, phone and reference, only if they appear in the text.
4
Ledger checks
Do those values match a real transaction on the wallet?
5
LLM drafts
A reply in the customer's own dialect. It decides nothing.
Confidence gateDecides where each ticket goes next.
Sure
To the right team's queue with the draft ready. The agent approves or edits it.
Not sure
To a person, with Jev's split shown so they see why.
Scam words
Always a person, marked urgent, whatever the confidence.
Jev never writes text, the LLM never routes, and a person sends every reply.

Models, tools and data

Small, cheap models.
Test data we can trust.

DecisionsJev (TypeSafe AI). Returns a probability for every option, so we know when it is unsure.
Reply draftsGPT-6 Astra, or a free model from the challenge's list. Swappable.
ExtractionPlain rules for amounts, phone numbers and references. No model can invent a number.
LedgerSQLite with 40 mock wallets and their transactions.
Agent screenPython backend, one web page: queue, draft, approve, edit, take over.

300 tickets

175 synthetic, for building
75 held out
50 human

Synthetic: an LLM writes tickets per category in dialect, English and Arabizi, with typos and mixed scripts. We read every one and throw out the fake-sounding ones.
Held out: never looked at while building. Only used for the final score.
Human: 50 tickets written by real Iraqis about real wallet problems. Scored on their own, so clean synthetic text cannot flatter us.

What could go wrong

A scam routed as routineScam words always go to a person
Jev down on Iraqi internetOne retry, then the ticket goes to people
A draft with an invented amountDrafts may only use values found in the ticket
Synthetic data too cleanHuman tickets scored on their own
Customer data in a model callPhone and card numbers masked before any call
